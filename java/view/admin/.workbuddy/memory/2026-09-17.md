## 排查：平台端与供应商端「全部订单」是否为同一页面

结论：是同一个文件 `src/views/order/order/List.vue`。

路由证据：
- 平台端：`src/router/asyncRoutes/admin/order.ts` → `order/list`（全部订单）→ `views/order/order/List.vue`
- 供应商端：`src/router/asyncRoutes/vendor/supplier.ts` → `order/list`（全部订单）→ 同样是 `views/order/order/List.vue`
- 路由集合由 `src/utils/menus.ts` 按 `localStorage.adminType` 切换：`admin` → adminRouters，`vendor` → vendorRouters，`shop`/`store` → merchantRouters
- 同一文件的差异来源：① VORT 条件编译（`@vort-if vendor|merchant|o2o` 等）；② 运行时 `adminType` 判断（如 `adminType === 'vendor'` 时显示「小计」而非「订单金额」）

容易混淆点：
- `src/views/vendor/supplier/order/List.vue` 名字像供应商端订单页，实际只被 `src/router/asyncRoutes/admin/organize.ts:108` 引用，是**平台端「供应商管理 → 供应商订单」**页面（name: vendorOrderManage）。
- `src/views/vendor/supplier/order/` 下的 `Info.vue`、`Deliverlist.vue` 及其 `src/` 子目录无任何引用（疑似遗留/死代码）；该页面的详情、批量发货等仍复用 `order/order/Info.vue`、`order/order/src/*`。
- 两端订单详情都通过 `components/dialog/src/DialogForm.vue` 的 `import.meta.glob("../../../views/**/*.vue")` 按 `path="order/order/Info"` 解析，指向同一份 `views/order/order/Info.vue`。

## 排查：订单详情价格口径被混淆（isVendorOrder 把「订单身份」当成「查看者视角」）

- 现象：平台端打开带 vendorId/vendorName 的订单，详情页价格列显示「供货价」、小计显示供应商小计、「订单金额」+OrderMoney 整块隐藏。
- 根因：`src/views/order/order/Info.vue:585`
  `const isVendorOrder = computed(() => adminType.value === "vendor" || hasVendorOrderIdentity(formState.value));`
  第二个 `||` 让「订单含供应商」等价于「供应商视角」。
- 来源：提交 `0d2fae80d`（2026-08-24「fix(order): 对接供应商订单供货价与小计」）把原来的
  `adminType.value === "admin" && hasVendorOrderIdentity(formState.value)` 改成了上面的写法。
  副作用：`shop` 查看供应商订单时 4 个编辑入口（收货人/配送方式/商品/订单金额）也被一并禁用（改动前只对 `admin` 生效）。
- 口径不一致：`List.vue` 同一处价格视角用的是纯查看者判断 `adminType === 'vendor'`（第 298、487、494 行），列表页正确、仅详情页错位。
- `hasVendorOrderIdentity`（`src/utils/orderShipPermission.ts:6`）本身用于「订单是否含供应商」是合理的，`List.vue:397/726` 的供应商标签与催促发货按钮就该用它，不应改。
- `Info.vue` 中 `hasVendorOrderIdentity` 仅 585 行一处用到（493 行 import）；若改为纯 `adminType === 'vendor'`，需同步清理该 import。
- 价格字段来源：`src/utils/orderSupplierPrice.ts` 的 `getSupplierOrderItemPrice` 取 `supplyPrice`（回退 `price`）、`getSupplierOrderItemSubtotal` 取 `subtotal`（回退供货价×数量）。

### 已实施的修复（用户确认口径：价格只按查看者身份）

改动文件：`src/views/order/order/Info.vue`（仅此一个，18 insertions / 17 deletions）

- 删除 `isVendorOrder` 计算属性，全部 11 处引用改为既有的 `isVendorAdmin`（`adminType === 'vendor'`），并把它的定义上移到原 `isVendorOrder` 位置，附口径说明注释。
- 受影响的 7 处展示逻辑：支付信息「小计/已支付金额」、商品表「供货价/价格」列、行小计、「合计」、`v-if="!isVendorAdmin"` 的「订单金额」标题与 `OrderMoney`。
- 受影响的 4 处编辑禁用：`isEditConsigneeDisabled` / `isEditShippingDisabled` / `isEditProductDisabled` / `isEditMoneyDisabled`。改后平台端与店铺端不再因"订单含供应商"被禁用，恢复以接口 `availableActions` 为准。
- 清理 `@/utils/orderShipPermission` 的 import，去掉不再使用的 `hasVendorOrderIdentity`（`canCurrentShopWriteOffOrder`、`isPlatformSelfOrder` 保留）。

未改动的相关位置（判断口径本来就是对的，别再动）：
- `views/order/order/List.vue` 298/487/494 行：纯 `adminType === 'vendor'`。
- `views/order/order/src/SubOrder.vue:143`：`isVendorAdmin = localStorage.getItem("adminType") === "vendor"`。
- `views/order/order/List.vue` 397/726 行用 `hasVendorOrderIdentity` 判断「订单来自供应商」标签与催促发货按钮 —— 这是订单身份语义，正确。
- `views/vendor/supplier/order/List.vue`（平台端「供应商管理 → 供应商订单」）无条件展示供货价，是该页面定位使然，未改。
